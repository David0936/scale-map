# scale-map 仓库设计：一个母仓库，每个产品一个子仓库

想直接上手，看 [使用教程](教程.md)。

> 每个产品，开始都是人类懒惰的发明；到了今天，都可以是一支广告。

## 为什么拆

系列会越做越长（扫地机 → 洗碗机 → 洗衣机 → …）。如果所有产品都堆在一个仓库里，会有三个问题：

1. **品牌合作要单独交付。** 「今天」那一格卖给品牌方后，要能把这一期整个交出去（镜头表、证据、场景代码、配乐、成片），而不是交出整个系列。
2. **方法和内容的节奏不同。** SKILL、镜头表规则、动画工具包是慢慢打磨的；每期产品是一次性冲刺。混在一起，一期的临时改动容易污染方法。
3. **仓库会变重。** 每期带预览视频和印样，十期之后母仓库就几百 MB。拆开后只拉需要的那一期。

所以：**母仓库放方法和工具，子仓库放产品。**

## 结构

<p align="center"><img src="images/repo-structure.png" alt="母仓库放方法，每个产品一个子仓库" width="360"></p>

```
scale-map/                         母仓库
├── SKILL.md                       方法：六层地图、五个阶段、质量门
├── references/                    画风圣经、镜头表模板、短片流程、交付格式
├── motion/
│   ├── kit/scale_map_kit.js       所有产品共用的动画零件（window.SM）
│   └── sync.sh                    把一支片子接上 huashu 引擎
├── cast/                          卡司：你的 IP 和宠物（david/ 默认，_template/ 模板）
├── templates/product/             新产品子仓库的骨架
├── tools/
│   ├── cast.sh                    建卡司、查卡司
│   ├── new-product.sh             新开一期：生成子仓库并挂到 products/<slug>
│   └── products.sh                读各期 product.yaml，生成 README 里的产品目录
├── docs/                          使用教程、这份设计、配图、系列介绍 PDF
└── products/
    └── robot-vacuum/  →  子仓库 scale-map-robot-vacuum

scale-map-<slug>/                  产品子仓库（一个产品一个）
├── product.yaml                   产品清单：论点、结尾问题、状态、卡司、片子、广告位、待办
├── cast/                          （可选）只给这一期用的卡司
├── README.md
├── films/
│   └── 60s/                       一个剪辑版本一个目录（以后可加 90s、竖版）
│       ├── 镜头表.md              镜头 + 史实与出处
│       ├── eras_ep<nn>.js         段落清单
│       ├── scenes/                每段一个场景文件
│       ├── score.py               纯代码配乐
│       └── previews/              风格方向、接触印样
└── publish/                       交付平台的成片
```

## 一期片子怎么流过仓库

<p align="center"><img src="images/pipeline.png" alt="从一句话到一支片的 8 步" width="360"></p>

| 步骤 | 产物 | 落在哪 |
|---|---|---|
| 1 一句话、查史实、论点 | 论点卡、六层地图、证据 | 子仓库 `product.yaml`（desire / thesis / question） |
| 2 新开一期 | 子仓库骨架 | `tools/new-product.sh` → `products/<slug>` |
| 3 镜头表 | 镜头 + 证据账本 | 子仓库 `films/<id>/镜头表.md` |
| 4 挑画风 | 三方向对比图 | 子仓库 `films/<id>/previews/` |
| 5 代码画、配乐 | 场景、段落清单、配乐脚本 | 子仓库 `films/<id>/scenes/`、`eras_*.js`、`score.py` |
| 6 门禁、交付 | 成片、交付说明 | 子仓库 `publish/`；母仓库 `tools/products.sh --write` 更新目录 |

母仓库在这条线上只出两样东西：规则（SKILL、references）和工具（motion、tools、templates）。

## 边界：什么放哪

| 东西 | 放哪 | 理由 |
|---|---|---|
| 讲故事的规则、门禁、画风圣经 | 母仓库 | 每期都用，改一次全系列受益 |
| 动画零件 `scale_map_kit.js` | 母仓库 | 跨产品复用；某期需要专用零件先写在那期的 scene 里，第二期也要用了再提进 kit |
| 镜头表、证据账本 | 子仓库 | 每个数字跟着它所属的产品走，交给品牌方时一起带走 |
| 场景代码、配乐 | 子仓库 | 只属于这一期 |
| 预览、成片 | 子仓库 `publish/` | 体积大；超过 50MB 改放 GitHub Release，仓库里只留链接 |
| 卡司（IP、宠物的定规和帧库） | 私人的在 `~/.config/scale-map/cast/`；公开的在母仓库 `cast/`；只给某一期用的在子仓库 `cast/` | 形象有版权和隐私，默认不进公开仓库；一套卡司可以给很多期用 |
| huashu 引擎 | 都不放 | 22MB 且有自己的许可证；`sync.sh` 复制到 `films/*/.work/`，已忽略 |

一条规则：**子仓库只依赖母仓库的 `motion/kit`、`sync.sh` 和卡司，不反向依赖。** 母仓库不知道任何一期的细节，只通过 `product.yaml` 读目录。

## product.yaml

母仓库唯一读取的产品文件。顶层字段一行一个（`tools/products.sh` 不装 YAML 库，只认这种写法）：

| 字段 | 例（EP01） |
|---|---|
| `slug` | `robot-vacuum`，也决定子仓库名 `scale-map-robot-vacuum` |
| `episode` | `1` |
| `name` | 扫地机器人 |
| `status` | `research → storyboard → preview → gated → published` |
| `desire` / `thesis` / `question` | 欲望、因果论点、消失之问，各一句 |
| `films` | 每个剪辑版本：路径、引擎片名、秒数、画风、状态、预览文件 |
| `cast` | `david`：这一期用哪套卡司（叙事 NPC ＋ 彩蛋），见 [cast/README.md](../cast/README.md) |
| `ad` | 广告位秒数、位置、适合的品类、是否已售 |
| `todo` | 发布前必须处理的事 |

`status` 与门禁对应：`preview` 表示有成片但没过 qa；`gated` 表示 qa、独立审片、deliver 全绿；只有 `gated` 才能改成 `published`。

## 日常用法

完整步骤和截图见 [使用教程](教程.md)，这里只列最常用的几条。

**新开一期**

```sh
tools/new-product.sh dishwasher 洗碗机 2
# 在 GitHub 建空仓库 David0936/scale-map-dishwasher 后：
git -C ../scale-map-dishwasher push -u origin main
```

**拉全系列**

```sh
git clone --recurse-submodules https://github.com/David0936/scale-map.git
# 已经 clone 过：git submodule update --init
```

**做一期片子**

```sh
cd scale-map
motion/sync.sh products/robot-vacuum/films/60s      # 打印渲染、配乐、qa、deliver 命令
```

**改了一期之后**：先在子仓库里提交并推送，再回母仓库提交指针（`git add products/<slug>`）。母仓库记录的是每期「定稿」的那个版本。

**只交付一期给品牌方**：直接给子仓库的访问权限，或 `git bundle create <slug>.bundle --all`。
